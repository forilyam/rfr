# rfr-gql-client

Инструкции действуют внутри `rfr-gql-client` в дополнение к [корневому AGENTS.md](../AGENTS.md). Маршруты, GraphQL-операции и сценарии авторизации описаны в [README.md](README.md).

## Назначение и окружение

SPA на React, TypeScript, Apollo Client и MUI. Сборка — Vite, dev-сервер — порт 3001. Модуль не включён в Gradle: команды npm выполняются из `rfr-gql-client`. Нужен Node 22+.

Для полного сценария нужны MySQL, `rfr-auth` на порту 9001 и `rfr-api` на порту 8081. Часть API работает с JSON-моками; учитывай это при проверке результата в интерфейсе.

## Где вносить изменения

| Каталог или файл | Ответственность |
|---|---|
| `src/pages` | Страницы приложения и OAuth callback/logout |
| `src/components` | Формы, карточки, таблицы, навигация и общие элементы UI |
| `src/components/AppContent` | Маршруты |
| `src/components/PrivateRoute` | Загрузка текущего пользователя и защищённая часть приложения |
| `src/hooks` | Именованные GraphQL-операции и работа с Apollo |
| `src/api` | HTTP-клиент авторизации, PKCE, токены, Apollo и ошибки GraphQL |
| `src/context` | Сессия, страны, диалоги и уведомления |
| `src/types` | Типы данных API |
| `src/theme.tsx` | Тема MUI |

## Правила изменений интерфейса

- Используй существующие компоненты MUI, тему и компоненты проекта. Не создавай собственный аналог доступного элемента библиотеки.
- Сохраняй разделение страниц, компонентов, хуков и API-клиентов. Новую GraphQL-операцию размещай в `src/hooks`, типы согласуй со схемой API.
- В формах учитывай начальное состояние, валидацию, сохранение и Reset; существующие правила находятся рядом с формами в `formValidate.ts`.
- Для запросов обрабатывай загрузку, пустой результат, ошибку и повторную попытку. Используй существующие `Loader`, `QueryErrorAlert` и snackbar.
- При изменении запросов учитывай обновление кэша и зависимых списков. Для ленты сохрани корректное поведение фильтров и `fetchMore`.
- Проверяй затронутый интерфейс в светлой и тёмной теме и на узком экране; используй возможности текущей темы и MUI.

## Авторизация и ошибки

- Используй существующий Authorization Code + PKCE в `src/api` и страницах авторизации. Не добавляй client secret в SPA.
- Apollo отправляет access token в `Authorization: Bearer`; `id_token` используется для logout hint.
- HTTP 401 очищает сессию через обработчик Apollo. GraphQL-классификации `UNAUTHORIZED` и `FORBIDDEN` распознаются отдельно в `graphqlError.ts`.
- Сообщения `BAD_REQUEST` и `NOT_FOUND` могут показываться пользователю; для остальных ошибок используй общий текст по существующему образцу.
- Успешный snackbar и обновлённый кэш не подтверждают сохранение. Для реальных операций проверяй данные повторным запросом или после перезагрузки.

## Настройки и команды

Vite читает переменные `VITE_AUTH_URL`, `VITE_API_URL`, `VITE_FRONT_HOST`, `VITE_FRONT_URL`, `VITE_CLIENT_ID`. При изменении адресов согласуй CORS, callback и logout URI с auth и API. Переменные `VITE_*` доступны браузеру: секреты в них не помещай.

Команды выполняются из каталога модуля:

```bash
npm ci
npm run dev
npm run build
npm run lint
npm run preview
```

`build` запускает TypeScript и Vite, `lint` — ESLint без допустимых предупреждений, `preview` раздаёт готовую сборку. Не меняй lock-файл и зависимости в несвязанной задаче.

## Проверка изменений

Для изменений TypeScript и UI используй сборку и lint. Для пользовательского поведения подбирай соответствующий сценарий в `rfr-e2e`; перед запуском тестов получи разрешение пользователя. Ручной проход интерфейса не заменяет результат JUnit-прогона. Не запускай `localenv.sh`.
