# rfr-e2e

Инструкции действуют внутри `rfr-e2e` в дополнение к [корневому AGENTS.md](../AGENTS.md). Устройство модуля и запуск описаны в [README.md](README.md).

## Назначение и окружение

E2E-тесты Rangiffler: JUnit 6, Playwright Java с `@UsePlaywright`, Allure 3, JDBC-фикстуры через `JdbcClient`. Нужны JDK 25, Chromium и работающий стенд: MySQL на 3306, auth на 9001, API на 8081, фронтенд на 3001.

Один source set — `src/test`; базовый Java-пакет — `io.student.rangiffler`. Проверка через Playwright MCP помогает исследовать UI, но корректность теста подтверждается JUnit-прогоном через Gradle.

## Разделение ответственности

| Пакет | Содержимое и границы |
|---|---|
| `config` | `TestConfig`: единственная точка чтения настроек |
| `jupiter/annotation`, `jupiter/extension` | Аннотации и JUnit extensions; без SQL и локаторов |
| `data` | `TestUser`, `UserFixture`, владение тестовыми данными; без зависимостей от JUnit |
| `data/db` | Подключения к БД, транзакции и чтение SQL-ресурсов |
| `utils` | Существующие генераторы случайных данных, включая `RandomDataUtils` |
| `ui/page`, `ui/component` | Page Objects и общие компоненты интерфейса |
| `test` | Сценарии по фичам (`auth`, `profile`); без локаторов и SQL |

SQL-ресурсы находятся в `src/test/resources/sql/auth` и `sql/api`. Не создавай новые архитектурные слои без согласования.

## Page Objects и сценарии

- Для создания и изменения страниц, локаторов, действий и UI-проверок используй [навык rfr-page-objects](../.agents/skills/rfr-page-objects/SKILL.md).
- UI сначала исследуй, затем выбирай локаторы по доступным ролям, именам и полям. Не придумывай локаторы без проверки интерфейса.
- Локаторы, действия и проверки элементов оставляй в страницах и компонентах. Подготовка данных, SQL и жизненный цикл JUnit им не принадлежат.
- Вход в тестах выполняй только через UI; токены в localStorage не подставляй.
- Сценарий описывает одно поведение. Для проверки сохранения профиля используй независимое чтение после перезагрузки; уведомление об успехе недостаточно.
- В Java, Gradle, SQL и properties этого модуля не добавляй комментарии и Javadoc: смысл передают имена и `@Step`.

## Данные и изоляция

- Для подготовленного пользователя используй цепочку `@User` → `UserExtension` → `UserFixture`; данные теста получай параметрами метода.
- Состояние конкретного теста хранится в `ExtensionContext.Store`. Не используй `ThreadLocal` или общее изменяемое состояние между тестами.
- Создание и удаление данных принадлежат фикстурам. Фикстура должна владеть своими записями и освобождать их при завершении сценария.
- Не выполняй широкие `DELETE` или `TRUNCATE`; очищай только записи своего пользователя с учётом зависимостей между схемами.
- Используй уникальные данные. Небольшие фикстуры размещай рядом со сценарием, крупные создавай во время выполнения; файлы записывай во временный каталог.
- Общие правила тестов из корневых инструкций, включая разрешения на запуск, изоляцию и ограничения ожиданий, остаются обязательными.

## Настройки

`TestConfig` выбирает непустое системное свойство `-Drfr.<ключ>`, затем переменную окружения, затем значение по умолчанию. Gradle передаёт свойства `rfr.*` в тестовую JVM.

| Свойство | Переменная окружения | По умолчанию |
|---|---|---|
| `rfr.frontUrl` | `RFR_FRONT_URL` | `http://localhost:3001` |
| `rfr.authUrl` | `RFR_AUTH_URL` | `http://localhost:9001` |
| `rfr.apiUrl` | `RFR_API_URL` | `http://localhost:8081` |
| `rfr.dbUrl` | `RFR_DB_URL` | `jdbc:mysql://localhost:3306` |
| `rfr.dbUser` | `RFR_DB_USER` | `root` |
| `rfr.dbPassword` | `RFR_DB_PASSWORD` | `secret` |
| `rfr.browser` | `RFR_BROWSER` | `chromium` |
| `rfr.headless` | `RFR_HEADLESS` | `true` |

В `dbUrl` не включай схему: её и параметры соединения добавляет код. Новые настройки добавляй в `TestConfig`, а не читай окружение из страниц или тестов.

## Запуск и отчёт

Перед каждым прогоном назови конкретные тесты; запуск и остановка разрешены согласно разделу «Разрешения агента» в корневом AGENTS.md. Команды выполняй из корня репозитория.

```bash
./gradlew :rfr-e2e:installPlaywright
./gradlew :rfr-e2e:test --tests '*RegistrationTest' --rerun-tasks
./gradlew :rfr-e2e:test --tests '*MainPageTest' --rerun-tasks
./gradlew :rfr-e2e:test --tests '*ProfileTest' --rerun-tasks
./gradlew :rfr-e2e:allureReport
```

Установка Chromium нужна при подготовке окружения. Стенд тесты не поднимают; не запускай `localenv.sh`. При падении различай недоступность стенда, ошибку сценария и дефект приложения. В отчёте укажи выбранный тест, результат Gradle и оставшиеся ограничения проверки.
