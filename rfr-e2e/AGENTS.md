# rfr-e2e

- Для изменения страниц, локаторов, действий и UI-проверок используй [навык rfr-page-objects](../.agents/skills/rfr-page-objects/SKILL.md).
- Перед выбором локаторов исследуй UI; не придумывай их без проверки интерфейса.
- Вход выполняй только через UI; токены в localStorage не подставляй.
- В Java, Gradle, SQL и properties этого модуля не добавляй комментарии и Javadoc: смысл передают имена и `@Step`.
- В тестах и JUnit extensions не должно быть SQL и локаторов. SQL и очистка данных принадлежат фикстурам, UI-действия и проверки — страницам и компонентам.
- Состояние теста храни в `ExtensionContext.Store`, без `ThreadLocal` и общего изменяемого состояния.
- Фикстура должна владеть своими записями и освобождать их после сценария. Не выполняй широкие `DELETE` или `TRUNCATE`.
- Новые настройки добавляй в `TestConfig`, а не читай окружение из страниц и тестов.
- Сохранение профиля проверяй независимым чтением после перезагрузки; уведомления об успехе недостаточно.
- Проверка UI через Playwright MCP не заменяет JUnit-прогон через Gradle.
