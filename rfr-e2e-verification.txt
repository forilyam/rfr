Результаты проверки тестовых данных и ресурсов rfr-e2e
Дата проверки: 30 октября 2026 года

ИТОГ

Четыре условия подтверждены. Изоляция мишеней подтверждена для штатного
запуска через Gradle, но аннотации @ProbeTarget в текущем коде нет.
Исходники и настройки проекта во время проверки не изменялись.
Диагностические файлы создавались только во временном каталоге.

1. Тесты не зависят от пользователей, созданных вне них

Подтверждено чтением всех 11 тестовых классов.

- Тесты входа, профиля и People получают пользователей через @User.
  UserRequest.fixture() создаёт основного пользователя через
  SingleUserFixture(TestUser.unique()).
- UserWithRelationsFixture создаёт каждого партнёра через отдельный
  SingleUserFixture(TestUser.unique()). Связи принадлежат тому же дереву.
- RegistrationTest генерирует TestUser.unique(), регистрирует пользователя
  через UI и очищает его в @AfterEach через SingleUserFixture.close().
- Негативный тест входа с несуществующим пользователем генерирует новый
  missing_<UUID>. Существующая учётная запись ему не требуется.
- FriendshipTest создаёт участников внутри каждого теста и освобождает
  фикстуры через try-with-resources.
- Мишени UserExtensionTest используют локально созданные объекты данных
  или собственные реальные фикстуры.
- @StaticUser используется только мишенями UsersQueueExtensionTest.

Зависимостей от заранее заведённых пользователей вне статического пула
не найдено. Это вывод по текущим исходникам; отдельный запуск на полностью
пустой базе данных не выполнялся.

Основные файлы:
  rfr-e2e/src/test/java/io/student/rangiffler/data/UserRequest.java
  rfr-e2e/src/test/java/io/student/rangiffler/data/UserWithRelationsFixture.java

3. После прогона в friendship нет тестовых связей

Подтверждено читающими SQL-запросами к схеме rangiffler-api.
Итоговый снимок сделан после полного прогона и отдельного запуска
UserExtensionTest без браузера. Ручная очистка БД не выполнялась.

Проверка                                         Исходно   После прогонов
Все строки friendship                             0         0
Связи с участником, чей username начинается rfr_  0         0

Запросы:
  SELECT COUNT(*) FROM friendship;

  SELECT COUNT(*) FROM friendship f
  JOIN user requester ON requester.id = f.requester_id
  JOIN user addressee ON addressee.id = f.addressee_id
  WHERE LEFT(requester.username, 4) = 'rfr_'
     OR LEFT(addressee.username, 4) = 'rfr_';

Итоговый общий COUNT равен нулю: таблица пуста целиком, а не только
в пределах выбранного префикса. Результат относится к моменту снимка.

Владение и очистка по коду:
  Store метода владеет корневой фикстурой и закрывает её автоматически.
  UserWithRelationsFixture хранит origin, partners и свои Friendship.
  TearDown закрывает свои связи, затем партнёров, затем origin.
  SingleUserFixture удаляет связи, профиль API и учётную запись.
  StaticUserFixture возвращает только свой заём и не выполняет SQL.

4. Мишени не выполняются самостоятельно

Для штатных Gradle-задач подтверждено запуском и чтением конфигурации.
В rfr-e2e/build.gradle для всех задач типа Test заданы исключения:
  exclude '**/UserExtensionTest$*.class'
  exclude '**/UsersQueueExtensionTest$*.class'

Listener сохранил все 47 внешних идентификаторов запуска:
  nested_standalone=0

Во внешнем плане не было самостоятельных тестов из вложенных классов
UserExtensionTest и UsersQueueExtensionTest. Эти классы выполнялись
внутри соответствующих проверок EngineTestKit.

Ограничение: @ProbeTarget не объявлена и не используется в текущих
исходниках. Изоляция основана на именах классов и Gradle-исключениях.
Защиты через аннотацию и запрета прямого запуска вложенного класса
из IDE сейчас нет. Прямой запуск через IDE отдельно не проверялся.

5. UserExtensionTest проходит без браузера

Подтверждено отдельным запуском только UserExtensionTest:
  19 тестов, 0 отказов, 0 ошибок, 0 пропусков; Gradle — 2 секунды.

Listener внутри forked JVM PID 57845 подтвердил переменные окружения:
  PLAYWRIGHT_BROWSERS_PATH=/private/tmp/rfr-resource-audit-ud5texxj/empty-browsers
  PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1

Указанный каталог был создан пустым и после запуска содержал 0 элементов.
В UserExtensionTest нет Page, Browser, Playwright или @UsePlaywright.
Прогону нужен MySQL: одна из мишеней проверяет реальную связь и профиль.

Ограничение: системный мониторинг всех процессов браузера не выполнялся.
Подтверждены успешный запуск с пустым путём браузеров, отключённой
загрузкой браузеров и отсутствие браузерного кода в проверяемом классе.
